# w00-d1 · Metal compute, the whole path

**After today you can say:** Metal is Apple's interface to the GPU. My kernel source gets compiled into a function, my arrays become buffers, a command that says "run this function over this many threads" is written into a command buffer, the GPU runs it, and the CPU waits for the result.

**Words you will meet.**
- *GPU*: the part of the chip built to run one small function on very many data items at once. The M5 in this Mac has 10 GPU cores.
- *Metal*: Apple's programming interface for the GPU, for both graphics and calculation.
- *Shader*: Metal's word for any function that runs on the GPU. The name comes from 3D graphics, where the first GPU functions computed colors. It has nothing to do with pictures here.
- *Kernel* (also *compute function*): a shader that runs a calculation, once per thread, over a grid of threads.
- *MSL*, Metal Shading Language: the language GPU functions are written in. It is C++ with some things removed.
- *Buffer*: a block of memory the GPU can read and write. Your arrays become buffers.
- *Command buffer*: a list of work for the GPU. You fill it, hand it over, and wait.
- *Dispatch*: the command that says "run this kernel over a grid of this many threads".

## Read (15 minutes)

**Main.** Apple, *Performing Calculations on a GPU*: https://developer.apple.com/documentation/metal/performing-calculations-on-a-gpu
Read the whole article, about 2,650 words. Stop at "Read the results from the buffer". Its 18 sections are in exactly the order the objects get used: write the GPU function, find a GPU, get the function, make a pipeline, make a queue, make buffers, make a command buffer, make an encoder, set the pipeline and the buffers, choose the thread count, encode, end, commit, wait, read. The code is Objective-C, one to five lines per snippet. You only need to read it, not write it. Apple's own words on the one thing people trip on: "MSL is a variant of C++ designed for GPU programming. In Metal, code that runs on GPUs is called a shader, because historically they were first used to calculate colors in 3D graphics."

## Code to read (8 minutes)

Both listings are verbatim from the article above. First the CPU version:

```c
void add_arrays(const float* inA,
                const float* inB,
                float* result,
                int length)
{
    for (int index = 0; index < length ; index++)
    {
        result[index] = inA[index] + inB[index];
    }
}
```

Then the same thing as a kernel in MSL:

```metal
kernel void add_arrays(device const float* inA,
                       device const float* inB,
                       device float* result,
                       uint index [[thread_position_in_grid]])
{
    // the for-loop is replaced with a collection of threads, each of which
    // calls this function.
    result[index] = inA[index] + inB[index];
}
```

Line by line, what is new:
- `kernel`: this function can be launched on the GPU over a grid of threads. It must return nothing.
- `device const float* inA`: a pointer into a buffer. `device` names the memory it lives in; every pointer in MSL must say that.
- `uint index [[thread_position_in_grid]]`: Metal fills this in with a different number for each thread. That number replaces the loop counter.
- The loop is gone. One thread does one `index`.

And the call sequence on the CPU, reduced to its seven lines (Objective-C, from the same article):

```objc
id<MTLFunction> addFunction = [defaultLibrary newFunctionWithName:@"add_arrays"];   // 2. the compiled function
// 3. pipeline state from the function    4. a command queue    5. three buffers    6. a command buffer and an encoder
[computeEncoder dispatchThreads:gridSize threadsPerThreadgroup:threadgroupSize];     // 7. run it over the grid
[commandBuffer commit];                                                               // hand the work to the GPU
[commandBuffer waitUntilCompleted];                                                   // the CPU waits here
```

In this repo you will never write those seven lines. Day 4 shows how MLX does all of them for you. The point of reading them today is that when something is slow or wrong later, you know which step it lives in.
