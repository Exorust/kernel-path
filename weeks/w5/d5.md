# Week 5, day 5 · Low precision and Blackwell

**Why this day.** The newest NVIDIA generation changed the matrix instruction again and added a new memory. The kernels that run on it are written for formats of eight and four bits. This page is what changed, why kernels break across generations, and what the same formats look like on your Mac.

## The story

**The formats.** Eight-bit floating point comes in two layouts: "an 8-bit floating point (FP8) binary interchange format consisting of two encodings - E4M3 (4-bit exponent and 3-bit mantissa) and E5M2 (5-bit exponent and 2-bit mantissa)" ([FP8 paper](https://arxiv.org/abs/2209.05433)). Below that, the microscaling formats, "Microscaling (MX) data formats that combine a per-block scaling factor with narrow floating-point and integer types for individual elements" ([MX paper](https://arxiv.org/abs/2310.10537)): a block of values shares one scale, and each value is four or eight bits. Week 2 day 5's affine quantization is the same idea with an integer; MXFP4 and NVFP4 are its floating-point cousins, and MLX already supports "mxfp4", "mxfp8", and "nvfp4" alongside "affine". NVIDIA's library for training in these formats states the hardware coverage: "FP8 training on NVIDIA Hopper, Ada, Blackwell, and Rubin GPUs" and "MXFP8 and NVFP4 training on NVIDIA Blackwell GPUs" ([Transformer Engine](https://github.com/NVIDIA/TransformerEngine)). The point of a narrower format is the roofline again: half the bytes per value doubles the operations per byte, which moves a memory-bound kernel toward the compute roof.

**Blackwell's break.** Colfax's first sentence on the subject: if you run a Hopper CUTLASS kernel on Blackwell, "the first thing that you'll notice is that it doesn't work." The reason: "The Hopper WGMMA instruction (in PTX, wgmma.mma_async) has been deprecated on Blackwell", replaced by `tcgen05.mma`, which "Unlike WGMMA, only one thread is used to launch", and which accumulates into a new memory: "TMEM is 256KB per SM in size, and is organized 2-dimensionally in 512 columns and 128 rows, or lanes, of 32-bit cells", so that "UMMA requires no registers for data, reducing the register pressure of MMA operations" ([Colfax, Blackwell](https://research.colfax-intl.com/cutlass-tutorial-writing-gemm-kernels-using-tensor-memory-for-nvidia-blackwell-gpus/)). Yesterday's regression, the tile that spilled registers because the accumulator lived there, is what tensor memory removes: the accumulator gets its own 256 KB. The PTX instructions are a family, `tcgen05.alloc`, `tcgen05.dealloc`, `tcgen05.mma`, and more, in section 9.7.18 of the ISA.

One trap the same post names: "the consumer Blackwell architecture (compute capability 12.0) differs from the data center Blackwell architecture (compute capability 10.0) in some major ways, notably lacking Tensor Memory." A consumer Blackwell card and a B200 are different targets with the same brand name; a B200 is what a cloud rents.

**The attention kernel caught in the middle.** FlashAttention-4, written for the B200, states the new problem: "tensor core throughput doubles while other functional units (shared memory bandwidth, exponential units) scale more slowly or remain unchanged", so that "shared memory traffic and exponential operations now dominate execution time, exceeding MMA compute by 25-60%" ([FlashAttention-4](https://proceedings.mlsys.org/paper_files/paper/2026/file/ae8b0b5838ba510daff1198474e7b984-Paper-Conference.pdf)). The matrix units got twice as fast and the softmax's exponentials did not. The limit moved from the multiply to the thing next to it. Week 6 day 1 has what they did about it.

**What this means.** NVIDIA's model is a new matrix instruction per generation, each reached first through PTX, each breaking the previous kernels, and a template library, CuTe, whose job is to make the port survivable. The cost shows in week 5 day 2's Triton gap and in every "Hopper only" line in a kernel's README. Apple's model is the opposite trade: one language, no published machine code, and a hardware generation that reshaped the roofline, the M5, exposed through a library, MPP, rather than through a new instruction set. On Apple you cannot write the tensor instruction; you call a primitive and the compiler chooses it. Neither is free. NVIDIA's gives the ceiling to whoever reads the PTX manual first; Apple's gives a stable kernel at the price of never seeing the floor.

**For the director.** Before a kernel for a rented NVIDIA machine, two questions: which compute capability, because 10.0 and 12.0 are different machines, and which precision, because the roof moves with it. On your Mac the second question is the same: the MLX formats are the Apple end of this page, and week 2 day 5's three regimes apply to each.

## Numbers to remember

| | |
|---|---|
| FP8 | E4M3 and E5M2 |
| Tensor memory | 256 KB per SM, 512 columns by 128 lanes of 32 bits |
| B200 against H100 | 2.25 against 1 PFLOPS BF16; exponentials and shared memory did not double |
| Compute capability | 10.0 datacenter with TMEM; 12.0 consumer without |
