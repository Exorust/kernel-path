# Week 1, day 1 · The chip

**Why this day.** Every kernel you will ever direct an AI to write for a Mac runs on one piece of silicon with one pool of memory. The numbers on this page are the ceiling for everything that follows. By the end you can take any model and say, from the chip's bandwidth alone, how fast it can possibly decode.

## How it works

**A system on a chip.** A desktop PC has a processor, a graphics card, and memory on three separate boards joined by cables and slots. An M-series Mac has all of them on one die, or two dies joined, inside one package. Apple's list for the M5 Pro and M5 Max: "a powerful CPU, scalable GPU, Media Engine, unified memory controller, Neural Engine, and Thunderbolt 5 capabilities" ([Apple, March 2026](https://www.apple.com/newsroom/2026/03/apple-debuts-m5-pro-and-m5-max-to-supercharge-the-most-demanding-pro-workflows/)). The memory chips sit next to the die in the same package, wired to one memory controller.

**Unified memory.** On a PC the graphics card has its own memory, and every array a program wants the GPU to see is copied across a cable into it. On the Mac there is one memory and one address space. Apple's definition from the first M1: "a unified memory architecture that brings together high-bandwidth, low-latency memory into a single pool within a custom package. This allows all of the technologies in the SoC to access the same data without copying it between multiple pools of memory" ([Apple, November 2020](https://www.apple.com/newsroom/2020/11/apple-unleashes-m1/)). The practical meaning for a kernel: the array you create in Python is the array the GPU reads. There is no transfer step, no "device memory" to run out of separately from RAM, and a 70-billion-parameter model at 4 bits, about 40 GB, fits on a 64 GB laptop with room for the cache.

What unified memory does not do is make all memory equally fast. Apple's compute talk says the copy "goes away", then adds the qualification: "The bandwidth to the cache is significantly higher, and with lower latency than of that to system RAM", and "Data reads become limited by the system memory bandwidth rather than the on-chip cache bandwidth" ([tech talk 10580](https://developer.apple.com/videos/play/tech-talks/10580/)). One pool, three speeds: registers inside a GPU core, caches on the die, and the memory chips in the package. Day 2 and day 5 go inside.

**Four engines on one memory.** The CPU, the GPU, the Neural Engine, and a fourth that Apple does not name. corsix/amx, the reverse-engineering project for that fourth unit, lists them: "(at least) four different ways for low-level programmers to perform heavy computations: 1. Standard ARMv8 SIMD/NEON vector instructions on CPU cores … 2. Apple's undocumented AMX instructions, issued from CPU, executed on a special accelerator execution unit 3. The Neural Engine (called ANE or NPU) 4. The GPU", and "Note that these instructions are neither documented nor supported by Apple" ([corsix/amx](https://github.com/corsix/amx)). Apple's phrase for AMX is "ML accelerators in the CPU". This course is about the GPU because it is the one engine you program in Metal; day 7 covers what the Neural Engine and the M5's GPU accelerators are for.

**Bandwidth is the first number.** Memory bandwidth is how many bytes per second the memory can deliver to the chip. For a model that is decoding one token, every weight is read once per token and almost no arithmetic is done per weight, so the time per token is the model's bytes divided by the bandwidth. Nothing a kernel does changes that floor; it can only approach it.

## Worked example: a decode floor from the chip alone

Take an 8-billion-parameter model stored in 4-bit weights. Bytes per token read: 8 billion weights times 0.5 bytes, about 4 GB, plus the key-value cache, which is small at short context.

| Chip | Bandwidth | 4 GB per token takes | Floor, tokens per second |
|---|---|---|---|
| M5 | 153 GB/s | 26 ms | 38 |
| M5 Pro | 307 GB/s | 13 ms | 77 |
| M5 Max | 614 GB/s | 6.5 ms | 154 |
| M3 Ultra | over 800 GB/s | under 5 ms | over 160 |

Compare with measured decode on llama.cpp from week 3 day 1: an M5 Max runs a 7-billion-parameter 4-bit model at 119.9 tokens per second, about 78 percent of this floor. The gap is the real kernel, the cache reads, and the gaps between kernels. The floor is the number to compute before any of those.

## What the sources say

Apple publishes bandwidth and GPU core count per tier:

| Chip | Memory bandwidth | GPU cores | Source |
|---|---|---|---|
| M4 | 120 GB/s | 10 | [Apple, Oct 2024](https://www.apple.com/newsroom/2024/10/apple-introduces-m4-pro-and-m4-max/) |
| M4 Pro | 273 GB/s | 20 | same |
| M4 Max | up to 546 GB/s | 40 | same |
| M5 | 153 GB/s | 10 | [Apple, Oct 2025](https://www.apple.com/newsroom/2025/10/apple-unleashes-m5-the-next-big-leap-in-ai-performance-for-apple-silicon/) |
| M5 Pro | up to 307 GB/s | up to 20 | [Apple, Mar 2026](https://www.apple.com/newsroom/2026/03/apple-debuts-m5-pro-and-m5-max-to-supercharge-the-most-demanding-pro-workflows/) |
| M5 Max | up to 614 GB/s | up to 40 | same |
| M3 Ultra | over 800 GB/s | two M3 Max dies | [Apple, Mar 2025](https://www.apple.com/newsroom/2025/03/apple-reveals-m3-ultra-taking-apple-silicon-to-a-new-extreme/) |

Max is twice Pro in both generations, and about four times the base chip. An Ultra is two Max dies: the M3 Ultra "links two M3 Max dies over 10,000 high-speed connections, providing over 2.5TB/s of low-latency interprocessor bandwidth, and making M3 Ultra appear as a single chip to software".

The M5 generation changed the compute side far more than the memory side: "a dedicated Neural Accelerator in each core, delivering over 4x peak GPU compute compared to M4", programmable "using Tensor APIs in Metal 4", while bandwidth rose "nearly 30 percent" ([Apple, Oct 2025](https://www.apple.com/newsroom/2025/10/apple-unleashes-m5-the-next-big-leap-in-ai-performance-for-apple-silicon/)). Four times the arithmetic with 1.3 times the bytes: kernels that were waiting on memory keep waiting on memory, and kernels that were waiting on arithmetic get four times faster. Week 3 day 2 shows the effect on matrix multiply.

Apple sells no datacenter GPU. It runs its own servers on its own chips: Private Cloud Compute's node is "custom-built server hardware that brings the power and security of Apple silicon to the data center" ([Apple Security](https://security.apple.com/blog/private-cloud-compute/)). Apple has not said why there is no server product, so any reason is inference. The consequence is not: the fastest Apple GPU you can target is in a laptop or desktop someone owns, and every Apple kernel is tuned for that.
