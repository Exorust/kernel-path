# Week 1, day 1 · The chip

**Why this day.** Every kernel you will ever direct an AI to write for a Mac runs on one piece of silicon with one pool of memory. The numbers on this page are the ceiling for everything that follows: nothing moves data faster than the memory bandwidth of the chip you own.

## The story

An M-series chip is a system on a chip. Apple's own description of the M5 Pro and M5 Max lists what sits on it: "a powerful CPU, scalable GPU, Media Engine, unified memory controller, Neural Engine, and Thunderbolt 5 capabilities" ([Apple, March 2026](https://www.apple.com/newsroom/2026/03/apple-debuts-m5-pro-and-m5-max-to-supercharge-the-most-demanding-pro-workflows/)). The part that matters for kernels is the phrase "unified memory". When Apple introduced the M1 it defined it this way: "a unified memory architecture that brings together high-bandwidth, low-latency memory into a single pool within a custom package. This allows all of the technologies in the SoC to access the same data without copying it between multiple pools of memory" ([Apple, November 2020](https://www.apple.com/newsroom/2020/11/apple-unleashes-m1/)).

On an NVIDIA machine, the GPU has its own memory and every array travels across a bus to get there. On a Mac there is no such trip. The CPU and GPU read the same bytes at the same address. That is why MLX can say arrays "are allocated in unified memory" and why a 70-billion-parameter model fits on a laptop with 128 GB: the whole pool is available to the GPU.

What unified memory is not: it is not uniformly fast. Apple's own compute tech talk says the copy between system RAM and video RAM "goes away", but also that "the bandwidth to the cache is significantly higher, and with lower latency than of that to system RAM" and "data reads become limited by the system memory bandwidth rather than the on-chip cache bandwidth" ([Apple tech talk 10580](https://developer.apple.com/videos/play/tech-talks/10580/)). One pool, but still a hierarchy. Day 2 goes inside the GPU core where that hierarchy lives.

**Four engines on one memory.** The CPU, the GPU, the Neural Engine, and a fourth one Apple does not name. The community reverse-engineering project corsix/amx states it plainly: there are "(at least) four different ways for low-level programmers to perform heavy computations: 1. Standard ARMv8 SIMD/NEON vector instructions on CPU cores … 2. Apple's undocumented AMX instructions, issued from CPU, executed on a special accelerator execution unit 3. The Neural Engine (called ANE or NPU) 4. The GPU", with the note that AMX instructions "are neither documented nor supported by Apple" ([corsix/amx](https://github.com/corsix/amx)). Apple calls that unit "ML accelerators in the CPU". This course is about the GPU, because that is the engine you can program directly in Metal. The Neural Engine runs Core ML models and is not programmable at the kernel level.

**The numbers that set the ceiling.** Apple publishes memory bandwidth per chip tier, and bandwidth is the number a kernel director reads first.

| Chip | Memory bandwidth | GPU cores | Source |
|---|---|---|---|
| M4 | 120 GB/s | 10 | [Apple, Oct 2024](https://www.apple.com/newsroom/2024/10/apple-introduces-m4-pro-and-m4-max/) |
| M4 Pro | 273 GB/s | 20 | same |
| M4 Max | up to 546 GB/s | 40 | same |
| M5 | 153 GB/s | 10 | [Apple, Oct 2025](https://www.apple.com/newsroom/2025/10/apple-unleashes-m5-the-next-big-leap-in-ai-performance-for-apple-silicon/) |
| M5 Pro | up to 307 GB/s | up to 20 | [Apple, Mar 2026](https://www.apple.com/newsroom/2026/03/apple-debuts-m5-pro-and-m5-max-to-supercharge-the-most-demanding-pro-workflows/) |
| M5 Max | up to 614 GB/s | up to 40 | same |
| M3 Ultra | over 800 GB/s | two M3 Max dies | [Apple, Mar 2025](https://www.apple.com/newsroom/2025/03/apple-reveals-m3-ultra-taking-apple-silicon-to-a-new-extreme/) |

Two patterns fall out of Apple's own figures. Max is twice Pro in both generations (546 against 273, 614 against 307). And Max is about four times the base chip. The M5 generation added something else: "a dedicated Neural Accelerator in each core, delivering over 4x peak GPU compute compared to M4", programmable "using Tensor APIs in Metal 4" (Apple, Oct 2025). Compute went up four times while bandwidth went up about 30 percent. Week 3 shows what that does to matrix multiply.

An Ultra is two Max dies joined: the M3 Ultra "links two M3 Max dies over 10,000 high-speed connections, providing over 2.5TB/s of low-latency interprocessor bandwidth, and making M3 Ultra appear as a single chip to software" (Apple, Mar 2025).

**No datacenter part.** Apple sells no GPU for servers. It does run its own servers on Apple silicon: Private Cloud Compute's "compute node" is "custom-built server hardware that brings the power and security of Apple silicon to the data center" ([Apple Security](https://security.apple.com/blog/private-cloud-compute/)). Apple has not published why there is no datacenter GPU product, so any reason you read is inference. The consequence for you is concrete: the fastest Apple GPU is a laptop or desktop chip, and every Apple kernel is written for a machine someone owns.
