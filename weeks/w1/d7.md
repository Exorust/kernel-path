# Week 1, day 7 · Metal 4, the M5 accelerators, and the Neural Engine

**Why this day.** The M5 put a matrix accelerator in every GPU core, and Metal 4 is how a kernel reaches it. Beside the GPU sits a second engine, the Neural Engine, that runs models through a different path entirely. Knowing which path is which, and what each can and cannot do, keeps you from asking an AI for a kernel on the wrong engine.

## How it works

**Two engines, two paths.** Day 1 listed four engines. Two of them run machine-learning models:

| | GPU | Neural Engine |
|---|---|---|
| Programmed through | Metal, MSL kernels; MLX | Core ML, from a converted model |
| You write | the kernel body | nothing at the kernel level |
| Apple's description | "directly programming the Neural Accelerators using Tensor APIs in Metal 4" | "Integrate machine learning models into your app" |
| Precision and shapes | what your kernel says | what the compiler decides |

Core ML's own definition: "A model is the result of applying a machine learning algorithm to a set of training data. You use a model to make predictions based on new input data" ([Core ML](https://developer.apple.com/documentation/coreml)). You train or convert a model, Core ML compiles it, and the system schedules it across the engines. Apple's reference implementation for transformers on the Neural Engine reports "up to 10 times faster and 14 times lower peak memory consumption compared to baseline implementations" on "an A14 or newer and M1 or newer chip", achieved by reshaping the model to the engine's preferred layouts rather than by writing kernels ([apple/ml-ane-transformers](https://github.com/apple/ml-ane-transformers)). That is the Neural Engine's deal: large gains for models that fit its rules, and no kernel-level control. This course does not go further down that path; it is the right path for a fixed model shipped in an app, and the wrong one for a kernel you want to shape yourself.

**What the M5 added to the GPU.** "M5 introduces a next-generation 10-core GPU architecture with a Neural Accelerator in each core, enabling GPU-based AI workloads to run dramatically faster, with over 4x the peak GPU compute performance compared to M4" ([Apple, Oct 2025](https://www.apple.com/newsroom/2025/10/apple-unleashes-m5-the-next-big-leap-in-ai-performance-for-apple-silicon/)). Before the M5, Apple's matrix instruction was day 3's `simdgroup_matrix`, a cooperative operation on the ordinary arithmetic units. The M5's accelerator is a unit in its own right, the Apple counterpart of NVIDIA's tensor core from week 5, and it is why week 3 day 1's prefill numbers jump 3.6 times between the M4 Max and the M5 Max on the same core count.

**How Metal 4 reaches it.** Three new pieces, from Apple's WWDC25 session on Metal 4 machine learning ([session 262](https://developer.apple.com/videos/play/wwdc2025/262/)):

- **MTLTensor**, "Metal 4's new resource for machine learning workflows": "MTLTensors are multi-dimensional containers for data", the first Metal resource that is an N-dimensional array rather than a flat buffer or an image. The documentation's one line: "A resource representing a multi-dimensional array that you can use with machine learning workloads" ([MTLTensor](https://developer.apple.com/documentation/metal/mtltensor)).
- **A machine-learning command encoder**, "the new MTL4MachineLearningCommandEncoder, which runs entire networks on the GPU timeline alongside your other draws and dispatches": a whole Core ML network as one command, next to your own kernels, in day 3's command buffer.
- **Shader ML and Metal Performance Primitives**, the part that matters for a kernel writer: "This year, Metal introduces Metal Performance Primitives to make MTLTensor operations accessible in the shading language. This library is a set of high performance APIs that enable performance portable solutions on MTLTensors. It provides matrix multiplication and convolution operations". The MPP guide's own summary: "Metal 4 introduces the tensor resource and the Metal Performance Primitives (MPP) framework for authoring machine learning kernels that leverage GPU neural accelerators in the Apple M5 chip", through "a library of compute primitives you can use inside a kernel to invoke threadgroup- or simdgroup-scoped operations on tensors" ([MPP guide](https://developer.apple.com/download/files/Metal-Performance-Primitives-Programming-Guide.pdf)). The code shape is one declaration and one call, `matmul2d<desc, execution_simdgroup> op;` on a descriptor that fixes the tile sizes, and the compiler routes it to the accelerator.

This is the difference from NVIDIA in one sentence. On Hopper you write the tensor-core instruction yourself, in PTX, and it changes on Blackwell. On the M5 you call a primitive inside a kernel and never see the instruction. Week 5 day 5 weighs the two.

**What the guide tells you to do with it.** The M5 starting points from the MPP guide, which week 2 day 3 uses: a 2 by 2 tile of simdgroups per threadgroup, a 32 by 32 tile per simdgroup for 16-bit operands, a K step of 128, Morton ordering of threadgroups, no threadgroup staging, no software pipelining. And its warning, which is day 2's register file: "Beyond a certain threshold, increasing simdgroup tile size may reduce performance if operands are too large to fit in fast thread-local memory."

**MLX's side.** MLX reaches the accelerators through kernels it calls NAX. On 2026-10-08 its tree held `nax.h` for matrix multiply and for attention, five NAX matrix variants (fused, gather, segmented, split-K, thin), `quantized_nax.h`, and NAX kernels for the linear-attention update and its backward pass. Week 3 day 2 reads one of them, the split-K kernel, with its 1.62x. From Python you do nothing to use them: the dispatch rules in MLX route shapes to NAX kernels on M5 hardware.

## Worked example: which engine, which path

Three jobs, and where each belongs:

1. A fixed image classifier shipped inside an app, run thousands of times a day. Core ML, Neural Engine. Convert once, let the system schedule it, accept no control over kernels.
2. A 27-billion-parameter language model decoding on your M5. The GPU through MLX, because the weights are quantized in a format you choose, the cache is managed by the engine, and the kernels of week 2 are the ones running. The accelerators help prefill, which is a matmul; decode is bandwidth-bound and they do not.
3. A matrix multiply with a very large inner dimension on an M5 Max. The GPU through MLX's NAX split-K kernel, or through MPP if you write it yourself. The accelerators are the whole point, and week 3 day 2's dispatch rule decides whether the kernel is used.

## Numbers to remember

| | |
|---|---|
| M5 accelerators | one per GPU core, over 4x peak GPU compute against M4 |
| Neural Engine transformers | up to 10x faster, 14x less peak memory, by layout changes not kernels |
| MPP M5 starting tiles | 2 by 2 simdgroups, 32 by 32, K step 128 |
| MLX NAX kernels | matmul, attention, quantized, gated delta, five matmul variants |
