# Week 1, day 8 · Who writes Apple kernels today

**Why this day.** Before you write a kernel, know who else does, where their code lives, what each repository is good for, and what is missing. The kernels you will direct an AI to build sit in a small, concrete landscape, and the gaps in it are where your work can matter.

## How it works

Four groups write the Metal kernels that run machine learning on Macs. For each, where the code is and what to read in it.

**1. Apple's MLX team.** The repository ml-explore/mlx, pushed daily (last push 2026-10-08, 28,696 stars), and the model code in ml-explore/mlx-lm (7,254). The kernels live under `mlx/backend/metal/kernels/`:

| Directory or file | What it holds | Read it for |
|---|---|---|
| `steel/gemm/` | the matrix multiply library: `mma.h`, `loader.h`, `gemm.h`, and the NAX variants | how 8 by 8 simdgroup matrices tile a block; week 2 day 3 |
| `steel/attn/` | the fused attention kernels | week 2 day 4 |
| `quantized.h`, `quantized_nax.h` | quantized matvec and matmul, 49 KB for the NAX one | the pre-scaling trick; week 2 day 5 |
| `reduction/`, `softmax.h`, `scan.h` | the primitives | the two-stage pattern; week 2 day 2 |
| `unary.h`, `binary.h` | elementwise templates | day 4's worked example |
| `scaled_dot_product_attention.cpp`, one level up | the dispatch rules that choose a kernel by shape | week 2 day 4 |

In mlx-lm, `mlx_lm/models/gated_delta.py` holds the linear-attention kernel of week 3 day 3, 647 lines with three Metal kernels inside Python strings. This code is Apple-authored, so with the MPP guide it is the closest thing to official guidance on how Apple wants kernels written.

**2. llama.cpp.** ggml-org/llama.cpp, 130,546 stars, pushed the same day. Metal kernels under `ggml/src/ggml-metal/kernels/`, 40 files on 2026-10-08. The largest is `mul_mv.metal` at 133,101 bytes, the quantized matvec; then `mul_mm.metal` at 56,349, `mul_mv_mma.metal` at 27,341, `dequantize.h`, a flash-attention family `fa_*.metal`, and `gated_delta_net.metal`. The host side has `ggml-metal-fusion.cpp` and `ggml-metal-tuning.cpp`, the schedule and the per-chip tuning tables of week 3 day 5. Week 3 day 1 tells how it began. Read it for the other answer to every week 2 question: a second, independent implementation of each kernel family, in plainer Metal than MLX's templates.

**3. Apple's libraries.** Metal Performance Shaders, MPS, is the older library of prebuilt kernels, closed source. Metal Performance Primitives, MPP, is the 2026 framework for the M5 accelerators from day 7, reachable inside your own kernels. Neither is code you read; both are what your kernel is measured against.

**4. The community.** Four repositories carry most of what is publicly known about the hardware.

- [philipturner/metal-flash-attention](https://github.com/philipturner/metal-flash-attention), 612 stars, last pushed 2024-09-22. The attention kernel that reached "a consistent 4400 gigainstructions per second on M1 Max (83% ALU utilization)". Its README records a hardware fact every Apple kernel writer meets: "Apple hardware lacks native FP32 atomics (`metal::atomic<float>` is emulated). While attempting to circumvent the lack of hardware support, bandwidth and parallelization bottlenecks in the FlashAttention-2 backward kernel were revealed. An alternative backward pass was designed with higher compute cost (7 GEMMs instead of 5 GEMMs)." More arithmetic was the price of a missing instruction. Read "Quantifying Performance" for how to score an Apple kernel in instructions, not FLOPS.
- [philipturner/metal-benchmarks](https://github.com/philipturner/metal-benchmarks), 634 stars, same date. The measurements behind day 2: register file, caches, instruction throughputs, all M1 and M2. Read the tables; nothing newer exists in public.
- [dougallj/applegpu](https://github.com/dougallj/applegpu), 711 stars, pushed 2026-10-06, still active: "reverse engineering the Apple G13 GPU architecture (as used by the M1)… a disassembler, an emulator and an assembler". The nearest thing to reading machine code on Apple; it targets the M1.
- [corsix/amx](https://github.com/corsix/amx), 1,275 stars, for the CPU's matrix unit.

Projects from 2025 and 2026 exist and are small: a tree-based speculative decoder for MLX at 145 stars, a KV-cache compression library with fused Metal kernels claiming "4.6x compression at 98% FP16 speed" at 113, a Triton backend for Apple GPUs at 22, batched linear algebra for MLX at 14. Their numbers are self-reported and unverified. The pattern is what to notice: the public Apple kernel world is a few hundred people, and the two most-cited repositories have not moved in two years.

**What is missing, stated carefully.** Apple ships a profiler: "The Metal debugger consists of a suite of tools for debugging and profiling your Metal app", with "performance counters and per-line shader profiling data" ([Xcode docs](https://developer.apple.com/documentation/xcode/metal-debugger)), and MLX can feed it with `MTL_CAPTURE_ENABLED=1` ([MLX Metal debugger doc](https://raw.githubusercontent.com/ml-explore/mlx/main/docs/src/dev/metal_debugger.rst)). So "no profiler" is false. What the research for this course could not find on 2026-10-08 is a scriptable per-kernel profiler of the kind NVIDIA's Nsight Compute provides, and a shared benchmark suite that two Metal kernels can be scored against. Week 4 is about both; the first has begun to close with macOS 27's command-line tools.

## Worked example: where to look for each question

| You want to know | Open |
|---|---|
| How MLX multiplies two matrices | `mlx/backend/metal/kernels/steel/gemm/mma.h`, then `loader.h` |
| Which attention kernel runs for your shape | `mlx/backend/metal/scaled_dot_product_attention.cpp`, the `if (query_sequence_length > 8)` branch |
| How a 4-bit weight is multiplied without unpacking | `load_vector` in `quantized.h`, or `block_q_n_dot_y` in llama.cpp's `mul_mv.metal` |
| What an Apple core's register file holds | metal-benchmarks README, On-Chip Memory table |
| What the compiler emitted for your kernel | applegpu's `compiler_explorer.py`, M1 only |
| Whether a kernel is at its limit | nothing scriptable; week 2's roofline and week 4's capture |
