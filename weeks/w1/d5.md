# Week 1, day 5 · Who writes Apple kernels today

**Why this day.** Before you write a kernel, know who else does, where their code lives, and what is missing. The kernels you will direct an AI to build sit in a small, concrete landscape, and the gaps in it are where your work can matter.

## The story

Four groups write the Metal kernels that run machine learning on Macs.

**Apple's MLX team.** The steel matrix kernels, the fused attention, the quantized matvec, and since the M5 the `*_nax` kernels for the neural accelerators, all inside the MLX repository, pushed daily (last push 2026-10-08). The team also writes the model code in mlx-lm, including the linear-attention kernel that weeks 3 and 4 return to. This code is Apple-authored, so it is the closest thing to official guidance on how Apple wants kernels written, together with the 2026 MPP guide.

**llama.cpp.** The Metal backend of the most-starred local inference engine, 130,546 stars, pushed the same day. Its kernels are in `ggml/src/ggml-metal/kernels/`, with the quantized matvec kernels as the largest files. Week 3 day 1 tells how it started.

**Apple's libraries.** Metal Performance Shaders, MPS, is the older library of prebuilt kernels. Metal Performance Primitives, MPP, is the 2026 framework for M5 neural accelerators, "a library of compute primitives you can use inside a kernel to invoke threadgroup- or simdgroup-scoped operations on tensors" ([MPP guide](https://developer.apple.com/download/files/Metal-Performance-Primitives-Programming-Guide.pdf)).

**The community.** Three repositories carry most of what is publicly known about the hardware.

- [philipturner/metal-flash-attention](https://github.com/philipturner/metal-flash-attention), 612 stars, last pushed 2024-09-22. An attention kernel that reached "a consistent 4400 gigainstructions per second on M1 Max (83% ALU utilization)". Its README records a hardware fact every Apple kernel writer meets: "Apple hardware lacks native FP32 atomics (`metal::atomic<float>` is emulated). While attempting to circumvent the lack of hardware support, bandwidth and parallelization bottlenecks in the FlashAttention-2 backward kernel were revealed. An alternative backward pass was designed with higher compute cost (7 GEMMs instead of 5 GEMMs)." More arithmetic was the price of a missing instruction.
- [philipturner/metal-benchmarks](https://github.com/philipturner/metal-benchmarks), 634 stars, same date. The measurements behind day 2. Both repositories are dormant, and both stop at the M2.
- [dougallj/applegpu](https://github.com/dougallj/applegpu), 711 stars, pushed 2026-10-06, still active: "reverse engineering the Apple G13 GPU architecture (as used by the M1)… a disassembler, an emulator and an assembler". It is the nearest thing to reading machine code on Apple, and it targets the M1.
- [corsix/amx](https://github.com/corsix/amx), 1,275 stars, for the CPU matrix unit.

Newer projects appeared in 2025 and 2026, all small: a tree-based speculative decoder for MLX (145 stars), a KV-cache compression library with fused Metal kernels claiming "4.6x compression at 98% FP16 speed" (113 stars), a Triton backend for Apple GPUs (22 stars), batched linear algebra for MLX (14 stars). Their numbers are self-reported and unverified. The pattern is the point: the public Apple kernel world is a few hundred people, and the two most-cited repositories have not moved in two years.

**What is missing, stated carefully.** Apple does ship a profiler: "The Metal debugger consists of a suite of tools for debugging and profiling your Metal app", with "performance counters and per-line shader profiling data" ([Xcode docs](https://developer.apple.com/documentation/xcode/metal-debugger)), and MLX can feed it: "To capture a GPU trace you must run the application with ``MTL_CAPTURE_ENABLED=1``" ([MLX Metal debugger doc](https://raw.githubusercontent.com/ml-explore/mlx/main/docs/src/dev/metal_debugger.rst)). So "no profiler" is false. What the research on 2026-10-08 could not find is a scriptable, per-kernel profiler of the kind NVIDIA's Nsight Compute provides, and a shared benchmark suite for Metal kernels that projects test against. Those two gaps are what week 4 is about, and the first one has started to close with the command-line tools in macOS 27.

**Why this matters for you.** Three facts from this page shape what an AI can and cannot do for you on a Mac. The hardware documentation is thin and partly reverse-engineered, so an AI's claims about the M5 core are guesses unless measured. The reference kernels are few and findable, so "do what MLX's steel kernel does" is a concrete instruction. And the gaps are real, so a measured, verified kernel for an open problem is rare enough to be noticed.

## The primary source

The [metal-flash-attention README](https://github.com/philipturner/metal-flash-attention), the "Quantifying Performance" section and the paragraph on FP32 atomics, 15 minutes. It is the best single piece of writing by someone who got an Apple GPU to 83 percent of its limit.
