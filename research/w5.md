## d4 Hopper
- Colfax TMA https://research.colfax-intl.com/tutorial-hopper-tma/: "TMA (Tensor Memory Accelerator) is a new feature introduced in the NVIDIA Hopper™ architecture for doing asynchronous memory copy between a GPU's global memory (GMEM) and the shared memory (SMEM) of its threadblocks (i.e., CTAs)." / "for a TMA copy, only one thread will be responsible for issuing the TMA operation."
- Colfax wgmma https://research.colfax-intl.com/cutlass-tutorial-wgmma-hopper/: "A warpgroup consists of four contiguous warps, i.e., 128 contiguous threads, where the warp-rank of the first warp is a multiple of four." / "A notable requirement of WGMMA is that operand B must always be stored in shared memory (SMEM). In contrast, operand A can be located in either SMEM or register memory (RMEM), and the accumulator C is always held in RMEM." / "Hopper introduces the asynchronous warpgroup-level matrix multiply and accumulate operation (WGMMA)."
- Shankhdhar worklog https://cudaforfun.substack.com/p/outperforming-cublas-on-h100-a-worklog (H100, BF16, cuBLAS = 716 TFLOPs): "The final kernel outperforms cuBLAS by 7% for N=4096. It fits in a single C++ file without any dependencies." / "Unfortunately, there's no documentation of these instructions in CUDA C++ guide and we have to look at PTX guide." / "This is not true for H100, where tensor cores are mandatory for high throughput." Progression: 32 TFLOPs → 317 ("a big jump over 32 TFLOPS of previous kernel"; tensor cores, TMA, barriers) → 423 (wgmma m64n128k16) → 498 ("128 x 128 tile sizes and QSIZE=5") → 610 → 631 → regression to "123 TFLOPs" with 128x256 tile ("insufficient register resources"; "Output tile uses 128 x 256 = 32768 registers in the thread block") → 660 ("L2 cache hit rate of 83%, meanwhile cuBLAS only hits 70%") → 704 ("98% performance of cuBLAS") → 734 ("102%") → 764 ("107%"). By size: "2% faster for N=512", "17% faster for N=1024", "7-8% faster for N=2048,4096", "1.5% faster for N=8192".
- DeepGEMM README https://github.com/deepseek-ai/DeepGEMM: "Despite its lightweight design, DeepGEMM's performance matches or exceeds expert-tuned libraries across various matrix shapes." / "DeepGEMM now achieves up to **1550 TFLOPS** on H800!" (2025.04.18) / "DeepGEMM leverages some concepts from [CUTLASS] and [CuTe], but avoids heavy reliance on their templates or algebras."
