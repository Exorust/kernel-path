## d2 Profiling on Apple
- Xcode Metal debugger https://developer.apple.com/documentation/xcode/metal-debugger: "Debug and profile your Metal workload with a GPU trace." / "the Metal debugger displays your Metal workload on a profiling timeline and offers detailed statistics like performance counters and per-line shader profiling data." / "To investigate GPU traces from the command line, use `gpudebug`, an interactive terminal-based debugger. Because its interface is text-based and self-discoverable, AI agents can run it autonomously to navigate traces, inspect state, and fetch resources to diagnose rendering issues without human intervention." Investigating GPU issues with AI agents: "For AI agents, point them at `man gpudebug` and a `.gputrace` file. That's all they need to start investigating autonomously." / "Trace loading and replayer startup can take seconds to minutes depending on the size of the trace". CLI: "The root has four children: `commands`, `performance`, `api_calls`, and `resources`." Counters: "The Performance counters feature is only applicable to Apple GPUs." / "The Metal debugger collects data from the passes running without overlap, so only one pass runs at a time on the device when the profiler measures the performance." Shader cost graph: "available for iOS devices with A17 Pro or later, and Mac computers with M3 or later."
- GPU counters API: "A GPU counter ([MTLCounter]) is typically a hardware feature that tracks a specific performance metric, such as timestamps before and after an important rendering stage." MTLCommonCounterSet: `timestamp`, `stageUtilization`, `statistic`; "Some GPUs may only support some of the counters within a counter set."
- WWDC21 10157: "using the Metal system trace in instruments, you can explore a timeline view that shows CPU and GPU durations for different rendering stages, GPU counters, and shader timelines." / "Below the encoders, you will find Occupancy, Bandwidth, and limiter counters." WWDC20 10603: "There's over 150 GPU counters to look at." WWDC26 388 https://developer.apple.com/videos/play/wwdc2026/388/: "On macOS, you can collect the data through metalperftrace, a new command line tool in macOS 27." / "you can also pass --json to make metalperftrace output in JSON format. Now you get structured output that can be easily fed into scripts for regression testing, or AI agents to automatically triage potential performance issues."
- MLX metal_debugger.rst: `MLX_METAL_DEBUG` build option; "To capture a GPU trace you must run the application with ``MTL_CAPTURE_ENABLED=1``." / "You can open and replay the GPU trace in Xcode. The ``Dependencies`` view has a great overview of all operations." dougallj/applegpu: "reverse engineering the Apple G13 GPU architecture (as used by the M1)"; `compiler_explorer.py` "Allows you to easily compile, extract, and disassemble shaders".
Gaps: whether gpudebug/metalperftrace give per-compute-dispatch counters UNVERIFIED (WWDC26 388 is about games); Xcode version shipping gpudebug not found.

## d3 AI-generated kernels, the evidence
- KernelBench-Verified https://arxiv.org/html/2607.16241 (2026-08-24): "frontier models frequently engage in reward hacking to artificially inflate reported performance." / "models often exploit the narrow test distribution by hardcoding bypasses for specific tensor values." / "(GPT-5.5) achieves a 0.88 geometric mean speedup, significantly lower than the 1.43 speedup observed under the standard evaluation protocol. No model consistently outperforms PyTorch when evaluated against realistic baselines." / "28% of GPU kernels generated by the best model increase peak GPU memory usage." / "the TF32 baseline adjustment primarily affects compute-bound problems (accounting for 21.2% of problems), while the hidden test suite addresses instances where models relied on distribution-specific exploits (affecting 11.6% of problems)." / Case H.1: "GPT-5.5 generates a shape-conditional identity bypass ... The model checks tensor metadata against known test configuration and returns input unchanged when matched, exploiting the fact that ReLU is identity on positive inputs." / "The 6 surviving hacks exploit benchmark configuration (hardcoded dimensions, test-specific numerical properties) rather than input distributions."
- KernelBench https://proceedings.mlr.press/v267/ouyang25a.html: "a suite of 250 carefully selected PyTorch ML workloads" / "frontier reasoning models perform the best out of the box but still fall short overall, matching the PyTorch baseline in less than 20% of the cases." / "results can improve by leveraging execution and profiling feedback during iterative refinement"
- Sakana, TechCrunch 2025-02-21 https://techcrunch.com/2025/02/21/sakana-walks-back-claims-that-its-ai-can-dramatically-speed-up-model-training/: "could effectively speed up the training of certain AI models by a factor of up to 100x." / "Sakana admitted that the system has found a way to "cheat" (as Sakana described it) and blamed the system's tendency to "reward hack"" / "the system found exploits in the evaluation code that the company was using that allowed it to bypass validations for accuracy". https://sakana.ai/ai-cuda-engineer/ now: "existing kernel generation benchmarks suffer from exploitable loopholes and insufficient diversity in testing conditions".
- Stanford CRFM https://crfm.stanford.edu/2025/05/28/fast-kernels.html: "Matmul (FP32): 101.3% performance of FP32 torch." / "Conv2D: 179.9%" / "Softmax: 111.8%" / "LayerNorm: 484.4%" / "FP32 is less common in modern ML workloads and often less optimized on recent hardware compared to FP16 or BF16, which may partly explain why it's easier to achieve performance gains over PyTorch with FP32 kernels." / "a multi-turn loop where a model incrementally edits a kernel, checks for correctness and performance, then tries again based on the result"
- NVIDIA SOL-ExecBench https://github.com/nvidia/sol-execbench: kernels "Checked for various forms of reward hacking", "Tested against a reference solution for numerical correctness", "Timed under reproducible conditions"; "SOL-Score: a metric that grades custom kernel performance based on the theoretical roofline of a NVIDIA B200 GPU".
Gaps: every benchmark is NVIDIA; no Metal equivalent.
